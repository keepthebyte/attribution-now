ChatGPT

By OpenAI. Documented UTM: utm_source=chatgpt.com (docs).

What works today

OpenAI publishes the utm_source=chatgpt.com value in its publisher FAQ, and ChatGPT adds it to every outbound link we tested on the web: citations, links in the answer text and links the user pasted. It keeps existing query parameters and inserts the tag before a #fragment. After a UI update in early October 2026, the tag was restored within about a week.

Send the chatgpt.com referrer on every web link location

Surfaces

Web

Tests

REF-01, REF-03

chatgpt.com already sets an origin referrer policy, but every outbound link also has rel="noopener noreferrer", so no referrer arrives and sites that rely on it count the visit as Direct.

Suggested fix

Drop noreferrer from the outbound link component and keep noopener. The page's existing origin policy then sends https://chatgpt.com/ and nothing more. Add a regression test that checks each link location.

Show prompt
You are working in the codebase for ChatGPT (Web).

Goal: improve attribution on outbound links so websites can see visits came from ChatGPT.

Current behavior (as of 2026-10-20, manual test):
chatgpt.com already sets an `origin` referrer policy, but every outbound link also has `rel="noopener noreferrer"`, so no referrer arrives and sites that rely on it count the visit as Direct.

Target behavior:
- REF-01: Request to the target carries `Referer` with the assistant's origin (e.g. `https://chatgpt.com/`).
- REF-03: Citation links use `noopener` without `noreferrer`; page/link referrer policy is `origin` or `strict-origin-when-cross-origin`.

Implementation guidance:
- Find where outbound links are rendered or opened for: inline citation in an answer; sources / citations panel; search result or link cards; shopping / product cards; map / place cards; deep research / research report; canvas / document / artifact view; link or URL written in answer text; link the user pasted, echoed back; shared conversation page (public share link).
- Web: remove `noreferrer` from citation links; keep `noopener`; set referrer policy to `origin` or `strict-origin-when-cross-origin`. Avoid `window.open(url, "_blank", "noopener,noreferrer")`.
- Add `utm_source=chatgpt.com` (the documented value) using safe merging: keep existing query and fragment, never overwrite existing utm_* params, skip signed/expiring URLs.
- Native apps: open links so the platform passes what it can (Android Custom Tabs with an app referrer); rely on the UTM where no referrer is possible.
- Add tests using these vectors: https://attribution.now/tests#test-vectors

Verify by opening https://attribution.now/t/check from each changed surface; the page shows the referrer and UTM it received.

Reference: https://attribution.now/best-practices

Keep sites' own UTM tags and signed URLs intact

Surfaces

Web, iOS app, Android app, macOS app, Windows app

Tests

MRG-03, MRG-04

ChatGPT already merges the tag cleanly into existing queries and fragments. Two edge cases remain: a link that already has utm_source=newsletter gets it replaced with chatgpt.com, and signed URLs (with signature or expires) get the tag appended, which can break them.

Suggested fix

Skip tagging when the URL already has a utm_* parameter or a signature/expiry parameter, as in the reference implementation and test vectors.

Show prompt
You are working in the codebase for ChatGPT (Web, iOS app, Android app, macOS app, Windows app).

Goal: improve attribution on outbound links so websites can see visits came from ChatGPT.

Current behavior (as of 2026-10-20, manual test):
ChatGPT already merges the tag cleanly into existing queries and fragments. Two edge cases remain: a link that already has `utm_source=newsletter` gets it replaced with `chatgpt.com`, and signed URLs (with `signature` or `expires`) get the tag appended, which can break them.

Target behavior:
- MRG-03: Target with existing `utm_source=newsletter` keeps that value.
- MRG-04: Target with `signature`/`token`/`expires` params arrives byte-identical.

Implementation guidance:
- Find where outbound links are rendered or opened for: inline citation in an answer; sources / citations panel; search result or link cards; shopping / product cards; map / place cards; deep research / research report; canvas / document / artifact view; link or URL written in answer text; link the user pasted, echoed back; shared conversation page (public share link).

- Native apps: open links so the platform passes what it can (Android Custom Tabs with an app referrer); rely on the UTM where no referrer is possible.
- Add tests using these vectors: https://attribution.now/tests#test-vectors

Pass an app referrer from the Android app

Surfaces

Android app

Tests

REF-01

The Android app carries the UTM tag, but no referrer arrives, so tools that rely on the referrer see Direct.

Suggested fix

Open links in a Custom Tab and set Intent.EXTRA_REFERRER to android-app://com.openai.chatgpt, so the browser can pass an app referrer.
